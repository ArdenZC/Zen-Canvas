# Canonical component anatomy

Candidate specification; owner review required. **Every component below inherits the complete common contract and its named state profile.** A dash/N/A means the state is semantically inapplicable, not unspecified. Dimensions are border-box CSS px. [Tokens](06-DESIGN-TOKENS-SPEC.md) own all values; [interaction grammar](06-STATE-INTERACTION-GRAMMAR.md) owns composition and lifecycle.

## Common contract for every component

- Compact/default resolve32/36px interactive controls, identical13/20/500 labels, icon16 and gap8. Container density propagates to all command peers. Body14/24/400, heading16/24/600, metadata12/16/400. Theme changes only semantic colors and elevation, never geometry.
- Width defaults to `min-width:0; max-width:100%`; field minimum160, ideal240, maximum480; button intrinsic width, min32/36. Command labels stay on one line. Chinese and English get identical boxes and no tracking. Long commands move intact to overflow; form labels/help wrap with control below; filenames truncate middle with extension retained and full accessible value. Content cannot be clipped solely to maintain a row height unless the row is explicitly virtualized and offers full details.
- Every focusable control has a localized accessible name. Label/help/error are programmatically associated. An icon never supplies the only accessible name. Native buttons/inputs/selects are preferred. Status/tone cannot be the only state signal.
- Default Light/Dark colors use surface/text/control-border; selected uses selected/selection-mark; focus uses focus; disabled uses text-disabled/surface-subtle with **no ancestor opacity**. Error/warning text, glyph and message are independent of selection/focus. Loading reserves the existing icon slot and label width, sets busy and prevents duplicate activation without moving focus.
- Keyboard focus uses a local2px text underline offset3–4; icon buttons use a12x2 bottom line and fields a24x2 bottom line. No surrounding frame. No shadows except explicit raised/floating hosts. Hover/press do not transform geometry. Touch/OS adapters may enlarge hit areas centrally; no feature exceptions.
- Narrow reflow may change host placement and hide optional metadata, never shrink font/icon/control height. A noninteractive container does not get hover/pressed/selected/focus/disabled/loading decoration; only its interactive descendants do. Its content can contain Notice/StateBlock.
- Forbidden overrides on **every** primitive: local px/rem metrics, radius, color, shadow, typography, opacity, selection/focus styles; arbitrary className/style hooks that affect owned anatomy. Content-renderer dimensions (image/code/media) remain domain-specific and cannot restyle chrome. New semantic variants require a central specification change and owner review.

## Component review contract

For every future primitive migration: compare computed dimensions and baseline in both densities, themes and locales; selected+focus and disabled+hover; long names/labels; narrowed host and scroll ending. Overlay changes additionally prove focus containment, Escape hierarchy, anchor flip/clamp and focus return. Row changes prove virtualizer height and ID-based selection parity. These are future acceptance requirements, not assertions that this HTML exercises production semantics.

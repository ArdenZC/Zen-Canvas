## Why requalification is allowed

The historical W6-10B RC1 qualification failed because the installed app did
not reach a usable Shell.

R1 diagnosis then proved:

- the exact RC1 starts successfully from a true clean profile;
- the historical failure reproduces with retained pre-release/dev application
  state;
- a specific persisted-state defect is not proven;
- there is no prior public Zen Canvas tag/release whose state forms a public
  upgrade-compatibility contract.

Owner disposition:

> retain RC1 and treat the retained pre-release/dev profile incompatibility as
> a non-blocking first-public-release residual only if RC1 passes a strict
> clean-profile requalification.

## Qualification profile rule

The original pre-release/dev profile is not the qualification profile.

Before qualification:

1. inventory the original active Zen Canvas app-data paths;
2. quarantine/rename them safely;
3. preserve them without deletion;
4. start RC1 from a truly clean normal app-data location.

Do not use `WEBVIEW2_USER_DATA_FOLDER` or other diagnostic overrides for the
release PASS path.

After qualification, restore the original pre-release/dev state unless Owner
explicitly changes that instruction.

## Hard RC1 self-state gates

Before the broader Windows matrix may count:

1. exact RC1 installs successfully;
2. clean-profile first launch reaches a usable Shell;
3. RC1 creates its own fresh app-data state;
4. normal app close succeeds;
5. relaunch using that RC1-generated state reaches a usable Shell;
6. uninstall succeeds with **application data retained**;
7. reinstall the exact same RC1 installer;
8. launch using the retained RC1-generated state reaches a usable Shell;
9. normal relaunch after that reinstall also succeeds.

Any FAIL or UNVERIFIED item above blocks RC1 and returns to Owner for RC2
disposition.

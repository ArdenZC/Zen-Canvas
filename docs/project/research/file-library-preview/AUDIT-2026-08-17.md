## Findings

### P1 — Master Plan source-of-truth wording conflicted with project governance

Before the audit, Master Plan §12.1 put “security/correctness constraints already enforced by authoritative production systems” first. That wording could be misread as making current implementation a prerequisite for safety authority.

`docs/project/README.md` already defines the correct model:

- normative safety/privacy/correctness contracts define what is allowed even when current code violates them;
- code/tests/schema describe current implementation truth and cannot silently weaken normative safety.

**Correction:** Master Plan now defers to the project README's source-of-truth precedence and repeats the normative-vs-descriptive distinction explicitly.

### P1 — Research evidence could be mistaken for contemporaneous original notes

PR #77 initially used wording such as “historical research evidence” and a chronological Round 1–4 synthesis. The exact original W-1 working notes, source revisions and chat/session boundaries were not preserved in the repository.

**Correction:** the research layer is now explicitly labeled a **reconstructed historical synthesis** produced on 2026-08-17 from surviving Zen conclusions/reviewed specifications and re-verified upstream facts. Round labels are a normalized reasoning reconstruction, not a claimed verbatim timeline.

### P1 — Mutable upstream URLs were insufficient for reproducible evidence

The initial evidence layer linked current upstream pages/repositories but did not pin the state used during re-verification.

**Correction:** `SOURCE_SNAPSHOTS.md` now records the exact Git revisions used for the 2026-08-17 re-verification where available, and clearly states that those revisions are not retroactive claims about the original W-1 research.

### P2 — License/clean-room matrix was incomplete

The initial matrix called out GPL/AGPL concerns for several projects but omitted or simplified other relevant current statuses.

**Correction:** the audited matrix now records:

- Spacedrive current README: FSL-1.1-ALv2 converting to Apache-2.0 after two years;
- Files: MIT;
- PowerToys: MIT;
- QuickLook for Windows: GPL-3.0;
- TagSpaces: AGPL-3.0 + commercial dual licensing, with Pro components proprietary;
- QLMarkdown: GPL-3.0;
- SourceCodeSyntaxHighlight: GPL-3.0;
- SpacePeek: commercial/freemium behavioral reference, with no source repository asserted.

The clean-room rule remains: research never authorizes source copying.

### P2 — Spacedrive historical mutation observation was classified too strongly

The original reconstructed Spacedrive note placed a surviving observation about ordinary path/OS mutation primitives inside “Official-source facts”. The exact original implementation revision supporting that W-1 observation was not preserved.

**Correction:** current pinned Spacedrive facts are separated from that historical Zen observation. The mutation statement is retained only as reconstructed context and cannot override Zen's dedicated filesystem mutation/recovery safety authority.

Contemporary similar utilities may be cited as comparison evidence, but none is claimed to be the exact original source.

## Authority conclusion

After this audit the intended hierarchy is explicit:

```text
normative safety/privacy/correctness contracts
        ↓
descriptive implementation truth (code/tests/schema)
        ↓
Master Development Plan
        ↓
reviewed specs / accepted ADRs
        ↓
active initiative
        ↓
STATUS / ROADMAP
        ↓
Track taskbook

research evidence = rationale/history, not implementation authority
```

The first two rows are different categories rather than a simple “code outranks docs” ordering: normative constraints remain binding when implementation violates them.

# ADR-0011 — Review-only Automation trigger boundary

Status: Accepted scope from Owner-reviewed, merged PM-02B activation PR #316. Implementation Owner review remains pending. This records authorized boundaries, not implementation acceptance.

One process-local Automation Trigger Coordinator waits on an explicit wake or the nearest durable due deadline. The existing scanner/watcher publishes filesystem truth and a root change clock in its own transaction; a postcommit wake is only a hint. Durable comparison recovers missed hints, coalesces a burst for five seconds, and holds event delivery while scope health is reconciling/unavailable. Metadata-only publication never advances this clock.

Calendar recurrence lives in `db/automation/calendar.rs`; Jiff owns IANA/DST calculations. Durable state/claim/cursor ownership lives in `trigger_state.rs`; schema/types/repository retain their separate boundaries. `runtime.rs` owns only the single condition-variable worker and cancellation/lifecycle. Existing WorkScheduler Background admission with bounded CPU/IO/handle hints and existing RuntimeResourceGovernor owns resource policy, fairness and backpressure. Idle waits indefinitely, with no application polling or per-Intent worker. Errors release leases and await a new hint.

The same `service.rs` transaction resolves fresh Query V2 scope, materializes the existing Organization Plan and stores a Run for manual and automatic requests. Existing Managed AI readiness, consent, currentness and queue admission remain authoritative. The latest referenced Plan in draft/building/ready/executing causes a blocked `automation_review_pending` receipt referencing that Plan and consuming that exact cause. Manual Run now remains available for every enabled configured trigger. No decision refresh, Dry Run, execution or filesystem mutation is added.

macOS uses its existing lifecycle owner: pause before sleep/unmount, recovery before releasing Automation. Windows adds only a native PowerRegisterSuspendResumeNotification callback because this Linux implementation host cannot prove that a relative condition-variable deadline wakes promptly after Windows resume. The adapter provides suspend/resume hints; no timer, recurrence, durable state, policy ownership or power polling. Registration/unregistration and coordinator cancellation/join share teardown; failed unregister retains callback context safely. Real suspend acceptance remains explicitly unverified until tested on native hardware.

Startup/wake recover durable state; neither is a configurable trigger. PM-03, autonomous mutation, Cleanup automation, Preference Memory and research runtime remain inactive. [Schema 37](../SCHEMA_37_AUTOMATION_TRIGGERS.md) and [activation taskbook](../tasks/AI-ONLY-PM-02B-EVENT-SCHEDULE-TRIGGER-ACTIVATION.md) define the contract.

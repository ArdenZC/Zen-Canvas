# Legacy Retirement Plan

This is the migration ledger for compatibility paths that still have production callers. A path is not deleted merely because the current V4.3 page no longer uses it directly; its deletion condition must be satisfied and verified in the same change.

| Legacy component | Current callers | Current authority | Reason it still exists | Migration required | Deletion condition | Risk |
| --- | --- | --- | --- | --- | --- | --- |
| `src/store/useOrganizeDecisionStore.ts` | `src/store/useOperationQueueStore.ts` uses it to preserve edited filenames during the older preview callback path; operation-queue and V4.2 compatibility tests cover that bridge. | Organization Plan ledger for Organize Files; Operation Preview and Operation Journal for execution. | It is still a narrow compatibility bridge for rename-preview continuity, not the Organize Files decision authority. | Move edited-name propagation into the authoritative operation intent/preview projection and remove the callback dependency. | No production caller remains; the compatibility tests are replaced by an Operation Preview/Journal regression covering edited names. | Removing it early can lose an edited filename or make an older preview callback silently fall back to the original name. |
| `src/store/useFileLibraryStore.ts` | App Shell/runtime providers, Scanner, Settings, Vault compatibility reads, Timeline, Rules/Rule Proposal, background indexing, scan manager, and operation queue. | File Library Query V2 and `LibrarySelectionV1`; durable scan/root, index, plan, analysis, and operation ledgers. | Several non-library surfaces still consume legacy scope, stats, scan, and AI projection state while the File Library migration is staged. | Migrate each caller to its owning durable query/projection store, then remove legacy scope/stats and mutation state from this store. | `rg` shows no production imports and all affected mounted flows pass with Query V2/ledger-backed state; no page derives an authoritative total from this store. | Deleting it now can break startup/runtime providers, Overview projections, scan controls, rules, or operation callbacks. |
| `src-tauri/src/global_index/legacy_queue.rs` | `src-tauri/src/global_index/mod.rs` includes the module; managed-AI classification enqueues and cancels through its bridge; legacy repair tests use the guarded cleanup helper. | Existing managed-AI queue and `ai_jobs` durable table, with provider policy and advisory classification boundaries. | The module is a compatibility adapter into the existing durable queue, not a second renderer/runtime queue. | Replace the adapter call sites with the final managed-AI queue API and retain an explicit migration/repair path for old `ai_jobs` rows. | All production classification and cancellation callers use the final queue API, old rows are covered by migration tests, and `legacy_queue.rs` has no runtime or repair-only callers. | Premature deletion can strand queued work, break cancellation, or remove rollback/repair coverage for existing durable jobs. |
| Legacy token aliases in `src/styles.css` (`--bg`, `--surface`, `--ink`, `--primary`, radius/easing aliases, and related names) | Automation dialogs, History/Restore surfaces, Vault cards, bootstrap/runtime UI, Timeline, Shell Chrome, Preview rows, and other older components. | `src/styles/tokens.css`, `src/styles.css` `--zc-*` tokens, and shared UI primitives. | The aliases are still used by production components that have not completed the design-token migration. | Migrate every caller to semantic `--zc-*` tokens and shared primitives; verify light/dark, high-contrast, and reduced-motion states. | A repository-wide production/reference search finds no alias usage except an explicit migration note, and visual regression coverage passes at supported densities and window sizes. | Removing aliases before callers migrate can produce silent color, radius, shadow, or motion regressions across older surfaces. |

## Review rule

The V4.3 renderer and backend authorities remain singular while these paths exist. Compatibility code may translate into the authoritative store or ledger, but it must not introduce a second decision, query, queue, execution, or recovery authority.
